# 参照データの加工(data/)

到達圏の計算に使う参照データ(250m メッシュの人口、DID の中の 125m セル、鉄道駅)を、1次メッシュごとの JSON にします。
JSON の形は `docs/interfaces-1103.md` の「参照データ」のとおりで、サーバーが `GET /api/ref/{mesh1}` で配ります。

## 使い方

元データを `data/raw/` に置いてから(入手元と置き方は `raw/README.md`)、次を実行します。

```bash
cd data
uv run dispatcher-data                        # data/raw にある1次メッシュすべてを data/out/ref/ に書く
uv run dispatcher-data --mesh1 6542 6642      # 1次メッシュを指定する(人口データが無い・海だけ・範囲外の1次メッシュも、空の JSON を書く)
uv run dispatcher-data --raw 別の場所 --out 別の場所
uv run pytest -q                              # テスト
```

実行すると、廃止駅として除いた線の数、1次メッシュごとに人口のセル数・人口の合計・DID のセル数・駅の数と、ファイルの大きさを表示します。
元データが足りなければ、どのファイルをどこに置くかを表示して 1 で終わります。

`--mesh1` で指定した1次メッシュは、人口・DID・駅のどれが無くても必ず書きます(web は参照データが1つでも 404 だと全体を使わないため)。
無いものは、空の `pop250`・`did125`・`stations` にします。駅と DID は、人口の元データが無くても元データにあれば入れます。
人口の元データに1行も無かった1次メッシュは、実行の最後に表示します。web は `pop250` に無い 250m セルを人口 0 とみなして調べないので、
その範囲に停留所があるなら、e-Stat の人口を `raw/mesh/` に置いて作り直してください。`--mesh1` を付けないときは、人口のある1次メッシュだけを書きます。

## 出力

`data/out/ref/{1次メッシュ4桁}.json`(UTF-8、空白なし。コミットしない)

| キー | 中身 |
| --- | --- |
| `mesh1` | 1次メッシュ(4桁) |
| `pop250` | 4分の1地域メッシュ(10 桁)→ 人口総数。0 人と、人口総数が数値でないセルは入れない。キーは並べ替え済み |
| `did125` | 中心が人口集中地区(2020年)の中にある 8分の1地域メッシュ(11 桁)。並べ替え済み |
| `stations` | 鉄道駅 `{name, line, operator, lat, lon}`。代表点の1次メッシュに振り分ける。駅名・運営会社・緯度の順 |
| `sources` | 出典の2行(取り決めの文言どおり) |

## 前提にした元データの形

| データ | 読むファイル(`data/raw/` から) | 文字コード | 使う列 |
| --- | --- | --- | --- |
| 人口 | `mesh/**/tblT001142Q*.txt`(e-Stat 統計表 T001142 を展開したもの) | Shift_JIS(cp932) | `KEY_CODE`(10 桁)、`HTKSYORI`(数を数えるだけ)、人口総数 `T001142001` |
| DID | `did/**/A16-*_DID.geojson`(複数あればファイル名の最後のもの) | UTF-8 | 形状(Polygon・MultiPolygon、[経度, 緯度]、JGD2011)。`A16_001` DIDid、`A16_003` 市区町村名称、`A16_006` 面積(km²)は確認用 |
| 駅 | `rail/**/UTF-8/N02-*_Station.geojson`(同上) | UTF-8 | 形状(LineString、[経度, 緯度]、JGD2011)、`N02_003` 路線名、`N02_004` 運営会社、`N02_005` 駅名 |
| 廃止された駅 | `src/dispatcher_data/closed_stations.csv`(リポジトリに入れてあるもの。元データではない) | UTF-8 | 駅名・事業者・路線・廃止日・出典URL(複数の URL は空白で区切る) |

### e-Stat の統計データ

- CSV で、見出しが2行ある。1行目は項目コード(`KEY_CODE,HTKSYORI,HTKSAKI,GASSAN,T001142001,…`)、2行目は項目名(`　人口(総数)` など)
- 人口総数の列は、2行目の項目名が「人口(総数)」の列(全角の空白とかっこをそろえて比べる)。見つからなければ、1行目が `T` + 6 桁 + `001` の列
- **秘匿処理**:`HTKSYORI` は 0 = 秘匿対象外、1 = 合算先、2 = 秘匿対象。定義書(T001142.pdf)によると、男女別人口(総数)は「秘匿しない項目」で、秘匿対象のセルにもそのセル自身の人口総数が入っている。合算先に足し上げられているのは年齢別などの項目だけ。そのため人口総数は各行の値をそのまま使い、秘匿対象を合算先に足したり引いたりしない
- **数値でない値**:人口総数が `*`・`-`・空などの数字でない値なら、そのセルは入れずに数を数えて表示する(令和2年の 6541〜6643 では 0 件)。0 人のセルも入れない
- `KEY_CODE` が 10 桁の地域メッシュのコード(ASCII の数字で、2次は 0〜7、分割は 1〜4)として読めない行は飛ばして数える。人口総数も ASCII の数字だけを数値とみなす

### 人口集中地区(A16)

- 各多角形の外接矩形と1次メッシュの重なりに入る 125m セルだけを調べ、セルの中心が多角形の中にあるかを shapely(`contains_xy`)で判定する。中心がちょうど境界上なら外とみなす
- 穴のある多角形・MultiPolygon も扱う。壊れた形は `make_valid` で直してから使う

### 鉄道(N02)の駅

- 駅は線で収録されているので、線の長さの半分の位置を代表点にする(緯度に応じて経度を縮めた平面で長さを測る)
- 同じ駅名(`N02_005`)・同じ運営会社(`N02_004`)の線は1つにまとめ、代表点は各線の中点の平均にする。`line` は路線名を「・」でつないだもの(データに出てくる順。例:旭川は「宗谷線・函館線・富良野線」)
- 同じ名前・同じ会社でも、既にまとめた線のどれからも 1,000m より離れていれば別の駅にする。2025年度版の全国のデータで、同じ駅の線どうしは最大 515m(土合)、同名の別の駅(JR東日本の大久保など)は 78km 以上離れていた
- 鉄道区分(`N02_001`)では絞らない(路面電車の停留場も入る)
- **廃止された駅**:N02-25 は 2025年12月31日時点のため、その後に廃止された駅の線が残っている(2025年3月の廃止分は既に入っていない)。`src/dispatcher_data/closed_stations.csv` に並べた駅を、駅をまとめる前に除く
  - 除く単位は N02 の線(feature)。事業者(`N02_004`)・路線名(`N02_003`)・駅名(`N02_005`)がすべて一致する線を除く。深川の留萌線の線だけを除くので、深川は函館線だけの駅として残る(代表点も函館線の線の中点になる)
  - CSV は UTF-8、見出しは `駅名,事業者,路線,廃止日,出典URL`。廃止日は `YYYY-MM-DD` で、記録として持つだけで、除くかどうかの判定には使わない(一覧にある線はすべて除く)。同じ(事業者・路線・駅名)を2行書くとエラー
  - `出典URL` の欄には、URL を空白で区切って複数書ける(URL に空白は入らない)。読み込むと `ClosedStation.source_urls`(URL のタプル)になる。出典の URL は記録で、判定には使わない
  - 除いた線の数を実行時に表示する。どの線にも一致しなかった行(新しい版の N02 で既に消えている、または書き間違い)も表示する。N02-26 以降を使うときは、一致しなくなった行を外す
  - 収録している駅:

    | 路線 | 駅 | 廃止日 | 出典 |
    | --- | --- | --- | --- |
    | 留萌線(深川〜石狩沼田) | 深川、北一已、秩父別、北秩父別、石狩沼田 | 2026-04-01(最終運行は 3月31日) | 廃止日・最終運行日・廃止区間:JR北海道「留萌線の鉄道事業廃止届の提出について」(2025年3月28日)https://www.jrhokkaido.co.jp/CM/Info/press/pdf/20250328_KO_todokede.pdf<br>駅名:JR北海道旭川支社「３月14日ダイヤ改正以降の留萌線運転時刻について」(2026年2月9日)https://www.jrhokkaido.co.jp/CM/Info/press/pdf/20260209_HP_AS_rumoiline.pdf |
    | 函館線 | 仁山、二股 | 2026-03-14 | JR北海道「2026年３月ダイヤ改正について」(2025年12月12日)https://www.jrhokkaido.co.jp/CM/Info/press/pdf/20251212_KO_kaisei.pdf |

  - 仁山・二股は、発表資料に駅の廃止が「ダイヤ改正日(2026年3月14日)」の項に書かれているだけで、営業の最終日は書かれていない。廃止日はダイヤ改正日の 3月14日とした。どちらも参照データの対象の1次メッシュ(6541〜6643)の外にあり、記録として入れている

### 地域メッシュ

JIS X 0410。計算は 8分の1地域メッシュ(緯度 1/960 度、経度 1/640 度)を単位にした整数で行い、境界上の点はそのセルの南西側の端を含む。
浮動小数の誤差で境界のごく近く(1行・1列の 1e-6 未満、約 0.1mm)にある値は境界にそろえる(web/src/reach/mesh.ts と同じ幅)。規則は取り決め(`docs/interfaces-1103.md` の「地域メッシュ」の表)どおりで、web のコードは import できないため Python で別に書いている。

## テスト

`tests/fixtures/raw/` に手作りの小さな元データ(cp932 の統計データ、辺がセルの境界に乗る DID、旭川・大久保などの駅)を置き、読み込み・秘匿処理・DID の判定・駅のまとめ方・メッシュコード・JSON の形を確かめる。
`data/raw/` に実データがあれば、1次メッシュ 6542 で人口の合計が数十万人であること、旭川駅が入ること、DID のセルが数千あり面積の合計が A16 の面積と 5% 以内で合うことも確かめる(無ければスキップ)。
`tests/test_refdata_verify.py` では、実装とは別の方法で作った値と突き合わせる:e-Stat の境界データ(`mesh/estat_mesh_boundary_250m_6542.zip`)とメッシュの範囲、1次メッシュ全体の総当たりと DID のセル、年齢別の列から見た秘匿処理(人口総数は合算されていない)、駅のまとめ方が線の順に左右されないこと、廃止された駅(留萌線の石狩沼田・秩父別・北秩父別・北一已)が入らず深川が函館線だけの駅になること、`closed_stations.csv` のすべての行が N02 の線に一致すること。
廃止駅の一覧の読み込み(見出し・廃止日・重複のエラー、出典URL を空白で区切って複数書けること)と、事業者・路線・駅名が一致する線だけを除くことは、手作りのデータでも確かめる(`tests/test_stations.py`、`tests/test_build.py`)。
`--mesh1` で指定した1次メッシュが、海だけ・範囲外(6540・6741・0000・9999)でも空の JSON になること、人口の元データが無い1次メッシュ(大久保のある 5339)でも駅は入ること、人口の元データが無い1次メッシュを実行の最後に知らせることも、手作りのデータで確かめる(`tests/test_build.py`)。
