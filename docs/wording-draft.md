#### 種類をまたぐ決まり

- **漢字とかなの使い分け**
  - 補助動詞（`〜してください`、`〜できます`、`〜ておく`、`〜てみる`、`〜ていただく`）と形式名詞（`〜すること`、`〜するため`、`〜のとおり`、`〜のとき`、`〜のほう`、`〜くらい`、`〜ほど`）はひらがなで書く。
  - 便や発車が「なくなる」は、現状では「無くなる」と「なくなる」が混在しているため、すべてひらがなの **「なくなる」** に統一する（「無い」も原則としてひらがなの「ない」にし、「有無」「無選択」などの熟語だけ漢字にする）。
  - 他動詞の連用形を1語だけ名詞にして「の」で目的語をつなぐ形（`対象便の確かめ`、`期間の確かめ`、`足し戻しの注意`）は使わない。定着した漢語の名詞（`対象便の確認`、`期間の確認`）にするか、動詞の形（`対象便を確かめる`、`便を平日に戻すときの注意`）に戻す。
- **かぎ括弧「 」の使い方**
  - 画面のボタン名、タブ名、手順名、判断材料のラベル、地図や表の記号を文中で指すときは、かぎ括弧「 」で囲む（例: `「承認する」を押してください`、`手順「2. 減便の方針」`、`「停留所で唯一の便」`）。
  - 現状ではボタン名に二重かぎ括弧『 』を使っている箇所（`chat.ts:L80` の `『新しく始める』を押してください`）があるが、画面の部品名はすべて一重のかぎ括弧「 」に統一する。二重かぎ括弧『 』は、かぎ括弧の中にもう一度括弧を入れるときと、チャット欄に入力する文面の例（`『調査を続けて』と送ってください`）だけに使う。
  - 単語を目立たせるためだけの強調のかぎ括弧は使わない。
- **丸括弧（ ）の中に入れてよいもの・入れないもの**
  - **入れてよいもの**: 単位、GTFS のファイル名・項目名・ID（`（trip_id）`、`（{id}）`、`（feed が base）`）、短い内訳・件数（`（全 {total} 件中）`）、法令や条文の番号（`（運輸規則第6条第1項）`）、短い前提の注記（`（補間はしません）`、`（ほかの便との重なりは含みません）`）。
  - **入れないもの**:
    1. **利用者に求める次の操作や確認の依頼**: `減便後の GTFS に運行日がありません(方針の期間を確かめてください)。` のように依頼や手順を括弧に入れず、括弧の外に出して `減便後の GTFS に運行日がありません。減便の期間を確かめてください。` と行う順に2文で並べる。
    2. **重要な副作用や警告**: `選んで足し戻すと、AI の下書きは捨てます` のように操作の結果としてデータが消える注意は、括弧に入れず独立した文にする。
    3. **二重括弧 `(( ))`**: 丸括弧の中にさらに丸括弧を入れない。内側の括弧を外すか、角括弧 `［ ］` やかぎ括弧 `「 」` に替える（例: `（うち、緯度・経度が地域メッシュの範囲外［(0, 0) など］のため計算から除いた停留所：{excludedStops} 件）`）。
- **「〜ので」「〜ため」の使い分け**
  - **「〜ため」**: エラー・注意・仕様の説明で、客観的な原因・理由・根拠を述べるときに使う（例: `祝日一覧を読めないため、祝日は表示していません。`、`平日ダイヤの運行日ではないため、「停留所で唯一の便」は表示していません。`）。
  - **「〜ので」**: AI との会話の案内など、利用者の次の操作へ穏やかにつなぐ説明で使う（例: `AI は下書きを作るだけなので、内容を確かめてから「承認する」を押してください。`）。
  - **混在の解消**: 同じ欄に並ぶ説明文（`RestoreStep.tsx:L495-503` や `tools.ts:L185-245` など）で、データ未読や計算未了といった客観的な理由に「〜ので」と「〜ため」を混ぜず、すべて **「〜ため」** にそろえる。また、1文の中で目的の「〜するため」と原因の「〜したため」を重ねない。
- **ボタン・手順・状態の名前と、説明文での呼び方をそろえること**
  - ボタンを押すよう案内するときは、ボタンの表示名と一字一句同じ語をかぎ括弧「 」に入れて書く（下書き確定のボタンを `承認する` に統一し、説明文の「適用する」「この内容で進める」をなくす）。
  - 下書きを取り消す操作も、ボタンが `やめる` なら説明文でも `「やめる」を押す` と書き、確認ダイアログや結果の説明では「破棄する（破棄されます）」にそろえる（「捨てる」「取り消す」「やめる」を無秩序に混ぜない）。
  - 他の手順を参照するときは、左の手順一覧の見出し（`「1. GTFS を読み込む」`、`「2. 前提情報」`、`「4. 影響（到達圏）」` など）と同じ名前で呼ぶ。
- **読点「、」と記号の決まり**
  - 短い主語・主題・目的語のすぐあとに間を作るだけの読点（`AI は、〜`、`ほかの手順は、すべて〜`、`この会話には、もう送れません。`、`期間中は、〜`）は外す。読点は、条件・理由・逆接の節の切れ目、長い主語や長い目的語の切れ目、並列の区切り、主題のあとに別の動作主が続く箇所、外すと掛かり先が変わる箇所だけに打つ。
  - 主語と述語の間に長い括弧や節を挟まない（`editText.ts:L128` のように主語「勤務は」と述語「確かめてください」の間に100字以上の括弧が入る文は、先に主語と述語をつなぎ、基準値は後ろに出す）。
  - 文頭にダッシュ記号 `—` を置いてエラー文を続けたり（`ChangeOrder.tsx:L498`）、説明・注意・エラーの文末の句点「。」を落としたりしない（`chat.ts`、`tools.ts`、`agent_relay.py`、`research.py` の句点抜けをそろえる）。
