# 11/3 の実装計画:GTFS を読み込んで到達圏を地図に出す

11/3 のゴールは、道北バスの GTFS を画面で読み込み、指定した日付・時間帯の到達圏を地図に色分けして出すところまでを一本通すことです。
減便の方針の適用と比較(11/4)、前提情報の調査と GTFS の出力(11/5)はこの日の範囲に入れません。

## 0. 先に済ませること(ご自身で)

コードを書く前に、次の元データを `data/raw/` に置いてください(置き場所は `data/raw/README.md`)。

1. 北海道オープンデータプラットフォームの利用フォームに記入し、道北バスの GTFS を `data/raw/gtfs/` に置く
2. e-Stat から、国勢調査(令和2年)の 250m メッシュ人口を、道北バスの運行範囲を含む1次メッシュの分だけ取る(125m は「参考」扱いのため、11/3 は 250m だけで足りる)
3. 国土数値情報から、人口集中地区(A16、2020年)と鉄道(N02、2024年)の北海道分を取る

ファイルがそろうまでは、テスト用の小さな GTFS(手書き)で進められます。

## 1. 作業の順番

| 順 | 作業 | 置き場所 | 確かめ方 |
| --- | --- | --- | --- |
| 1 | 画面の土台:Tailwind CSS と shadcn/ui の導入、MapLibre で OSM Japan の地図を出す。左に手順、右に地図の1画面 | `web/` | 地図が出て、出典表示が見える |
| 2 | GTFS の読み込み:ZIP を JSZip で開き、Papa Parse で各ファイルを読む。Web Worker で動かす。**11/2 に済み**:`loadGtfsZip`、ファイル選択と「サンプルを読み込む」(道北バス)のボタン、ファイルごとの行数の表示。**残り**:Web Worker に移す、型の変換 | `web/src/gtfs/` | 手書きの GTFS でテスト。サンプルがあれば件数を確認 |
| 3 | 運行日の判定:日付を与えると、その日に走る service_id の集合を返す(calendar と calendar_dates の両方) | `web/src/gtfs/` | 曜日、期間の端、exception_type 1・2 のテスト |
| 4 | 時間帯ごとの出発:その日に走る便から、停留所ごとに出発がある時間帯を求める。24時を超える時刻、乗車できない停留所(pickup_type=1)を扱う | `web/src/gtfs/` | 25:10 の出発、乗車不可の停留所のテスト |
| 5 | 125m 格子:8分の1地域メッシュ(緯度 3.75秒 × 経度 5.625秒)のコードと座標の変換。停留所・駅から最大の徒歩圏(1,600m)以内のセルだけを作る | `web/src/reach/` | 既知の地点でメッシュコードを照合するテスト |
| 6 | 参照データの加工:250m メッシュの人口密度、125m セルが DID の中か、鉄道駅の点(駅の線から代表点を取る)を、1次メッシュごとに書き出す | `data/` | pytest。北海道の一部で件数を確認 |
| 7 | 参照データの配信:FastAPI で `data/out/` を返す。開発中は Vite のプロキシでつなぐ(プロキシとサンプル GTFS の配信は 11/2 に済み) | `server/`、`web/vite.config.ts` | pytest、画面から取得できる |
| 8 | 到達圏の計算:セルを都市部・郊外・中山間に分け(しきい値は画面で変更可)、kdbush で、その時間帯に出発がある停留所・駅が徒歩圏にあるかを判定する。Web Worker で動かす | `web/src/reach/` | 小さな格子での手計算と一致するテスト |
| 9 | 地図の表示:到達圏から外れるセルを色分けし、時間帯(3時間ごと、1時間ごと)と日付を切り替える。停留所も表示する | `web/src/map/` | 画面で確認し、録画しておく |

順 2〜5 は参照データが無くても進められます。順 6 は元データがそろってから着手します。

## 2. 決めておきたいこと(11/3 の朝まで)

- **鉄道駅の時間帯の扱い**:鉄道の時刻表データは手元にありません。11/3 は「駅は 6〜24時のすべての時間帯で使える」とみなす案で進めます。駅の始発・終電を入れるかは後で決めます
- **地図の描き方**:セルの数が多い場合、GeoJSON の面で描くと重くなります。まず GeoJSON で描き、重ければ画像(キャンバス)に描いて重ねる方法に切り替えます
- **値の前後の空白**:読み込みでは元の値をそのまま残す(出力を入力と同じにするため)。順 3 以降で service_id・trip_id・stop_id などを照合するときだけ、キーの前後の空白を取る(gtfs-reviewer の提案)
- **公開時のサンプル配信**:`/api/sample-gtfs/download` を合言葉の対象に入れるか。CC BY 4.0 なので再配布はできるが、帯域を使う
- **祝日一覧**:内閣府の CSV を使うのは 11/4 の方針の適用からです。11/3 は日付を手で選ぶだけにします

## 3. その日のうちに残すもの

- 機能が1つ動くたびにコミットする(日本語のメッセージ)。期間中に作ったことをコミット履歴で示すため
