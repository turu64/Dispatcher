# 実物を確かめたうえでの修正要件

利用者が画面の実物を確かめて挙げた指摘を、修正要件として記録する。ここではまだ実装しない。指摘がそろってから、タスクに分けてまとめて直す。

- 番号は、利用者が挙げた順
- 「指摘」は利用者の言葉の要約。「補足」は指示役が調べたことや、今の作り。「決めること」は、直す前に決める点

## 1. 日付を選ぶカレンダーに、祝日を色で出す(11/3)

- **指摘**:日付を選ぶカレンダーに、祝日を反映した色付けをするべき
- **補足**:
  - 今は、ブラウザ標準の日付の欄(`input type=date`)を使っている。標準の欄は、日ごとに色を変えられない。カレンダーの部品(shadcn/ui の Calendar など)に替える必要がある
  - 該当する欄は、方針の期間の開始日・終了日(`PolicyStep`)と、到達圏を比べる日(`DateBandStep`)
  - 祝日は、内閣府の祝日一覧(`store/holidays.ts`)から取れる
- **決めること**:
  - 色の付け方。日本のカレンダーの慣例(日曜・祝日は赤、土曜は青)にするか
  - 祝日の名前を出すか(マウスを載せたときなど)
  - 入力の GTFS の有効期間の外の日を、選べないようにするか、薄く出すか
  - その日にどのダイヤ(平日・土曜・日祝)が走るかも、カレンダーに出すか

## 2. 減便の方針で出る「差」の表示が分かりにくい(11/3)

- **指摘**:手順2(減便の方針)で出る差の表示が分かりにくい。デザインを改善する必要がある。「公示第46・47号」とは何か
- **補足**:
  - 公示第46号・第47号は、北海道運輸局が出している公示で、バスの運行回数を減らしたときの届出に関わる。出典は `docs/research/dia-planning.md` の [N2]・[N3]
    - 第47号:運行回数を数える時間帯を決めている。旭川などの区分は 6〜9時台・10〜14時台・15〜19時台・20時台〜翌5時台
    - 第46号:その時間帯の回数がどの範囲まで減ってよいかを決めている。範囲の中なら、事前の届出ではなく事後の届出で済む場合がある
  - 画面では、系統ごと・第47号の時間帯ごとの便数の前後の表と、11〜15回の系統が10回以下になるときの「公示第46号の表の下限を下回ります」の注意に使っている(`docs/interfaces-1104.md` §6)。届出の区分は判定せず、「運輸支局に確認してください」と添えている
  - 説明なしに公示の番号だけを出しているので、何の表かが伝わらない
- **決めること**:
  - 差をどう見せるか(例:平日の便数の前後を大きく出す、消える便・入る便・同じ便を図で見せる、全曜日で便が無くなる系統を先頭で強調する)
  - 公示の表を、言い換えた名前(例「届出の目安:時間帯ごとの便数」)と短い説明で出すか、別の欄に分けるか、運行管理者向けに折りたたむか

## 3. 手順を、ステッパー(段階ごとの画面)に分ける(11/3)

- **指摘**:全部の手順(1〜6)を同じサイドバーに並べてスクロールさせるのは、操作の上で現実的でない。各手順をステッパーに分け、スクロールで全部が見えないようにする
- **補足**:
  - 今は、左の欄に「1. 読み込み」〜「6. 出力」を縦に並べている。下の「AI に相談」の欄も、同じ左の欄にある
  - CLAUDE.md の「画面は1画面。左に手順、右に地図」は、ステッパーにしても保てる(1画面のまま、左の中身が手順ごとに替わる)
- **決めること**:
  - 手順の間の移り方(「次へ」「戻る」、上のステッパーの見出しから直接移れるか)
  - 前の手順が済んでいないときに、先の手順へ移れないようにするか
  - 手順の区切り。今の6つのままか、まとめ直すか(例:「日付と時間帯」と「到達圏」を1つにする)
  - 「AI に相談」の欄の置き場所(どの手順でも出すか、手順の外の別の欄にするか)
  - AI の下書きの知らせの「手順2へ移る」などのボタンを、ステッパーの移動につなぐこと

## 4. 地図の出し分け、幅の調整、データの出典を別ページに(11/3)

- **指摘**:
  - 地図が要る手順と要らない手順で、地図を出すかどうかを切り替える
  - サイドバーと地図の幅を、利用者が調整できるようにする
  - データの出典はサイドバーに出さず、サイトの運営情報として、お問い合わせ(利用者本人)などと一緒に別ページに分ける
- **補足**:
  - CLAUDE.md の「データの出典を画面と README に表示する」は、別ページでも画面に出ていれば満たせる。直すときに CLAUDE.md の書き方も合わせる(どの画面からも、別ページへのリンクで出典に行けること)
  - 出典の欄は今 `web/src/components/DataSources.tsx` で、左の欄の下に出している
  - 背景地図の OpenStreetMap の表示(©OpenStreetMap Contributors)は、地図の上の表示として残す(地図を出すときは地図の中に要る)
- **決めること**:
  - どの手順で地図を出すか。たたき台:読み込み(停留所の分布)・日付と時間帯・到達圏・足し戻しは出す。減便の方針と出力は出さない(方針の手順で、全曜日で便が無くなる系統を地図に出したいなら出す)
  - 幅の調整の形(区切りをドラッグする。最小と最大の幅。調整した幅をブラウザに覚えておくか)
  - 別ページの中身(データの出典、お問い合わせ、作品の説明、ライセンス(MIT)、ハッカソンの作品であること)と、ページへの行き方(画面の上の端のリンクなど)。お問い合わせの連絡先を何にするか(メール、GitHub など)
